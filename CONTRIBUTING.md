# Как помочь

Опечатку можно исправить прямо в браузере: открой статью на сайте → **Исправить на GitHub** → измени текст → **Propose changes** → открой PR. GitHub сам создаст форк, если у тебя нет доступа к репозиторию.

Для нового вопроса скопируй [шаблон статьи](docs/article-template.md) в `src/content/articles/ponyatnyy-slug.md`. Один вопрос — один файл. Затем открой PR. Не знаешь ответа — [предложи вопрос](https://github.com/set-night/mospolytech-help/issues/new?template=question.yml).

## Требования к статье

- Сначала короткий ответ, затем шаги и исключения. Пиши понятно студенту.
- Укажи прямой первоисточник в `sources`, а для пересказа — ещё и исходный материал. Не копируй чужой текст без разрешения.
- Суммы и сроки привязывай к учебному году. Не выдумывай контакты и не публикуй личные данные.
- `reviewedAt` — дата сверки или импорта в формате `YYYY-MM-DD`.
- `verified` — ты действительно сопоставил ответ с источником; `community` — опыт студентов; `needs-review` — ответ ещё надо проверить. Официальный URL сам по себе не подтверждает пересказ.
- Категории: `start`, `study`, `campus`, `money`, `documents`, `admission`, `community`, `career`.
- В `tags` добавь слова, которыми студент будет искать ответ. Описание — до 240 символов. HTML и исполняемые ссылки запрещены.

## Локально

Node.js 24 LTS и npm:

```sh
npm ci
npm run dev
```

Поисковый индекс создаётся при сборке. Для полной проверки поиска:

```sh
npm run check:content
npm run check
npm run build
npm run check:links
npx playwright install chromium
npm test
```

На NixOS передай путь к своему Chromium через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Для WebKit в CI используется Ubuntu; локально включи `PLAYWRIGHT_ALL_BROWSERS=1` после `npx playwright install webkit`.

```sh
npm run format
npm run preview
```

## PR и проверки

CI проверит форматирование, TypeScript, схему и безопасность Markdown, ссылки, сборку и браузерные сценарии. В Actions появятся `browser-report` и сборка `site`. Чтобы посмотреть скачанную сборку, распакуй её и запусти статический сервер, например `npx serve .`.

PR не получает доступ к секретам. Публикация происходит после merge в `main` и успешных проверок. Правки CI и инфраструктуры просматривает владелец проекта. Превью PR доступно как артефакт; публичные preview-деплои из недоверенных форков отключены.

Коммиты: `docs(content): уточнить порядок заселения`, `fix(search): исправить поиск с клавиатуры`. Без подписей генераторов и соавторства инструментов.
